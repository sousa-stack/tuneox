# TuneOx

Open-source rekordbox alternative. Rust core (`crates/`) + Tauri 2 desktop app (`apps/desktop/`). GPL-3.0. Read [docs/architecture.md](docs/architecture.md) before making structural changes.

## Quality bar

These decide whether a change is done:

- USB exports must load correctly on every Pioneer/AlphaTheta player, in both Device Library and OneLibrary formats.
- Cue edits, waveform scroll/zoom and search respond on the next frame. Never make the UI await a disk write or a core round trip on an interactive path (see "Latency rules" in the architecture doc).
- Faster than rekordbox at startup, search and analysis.

- Every feature is a command in the core first, reachable from the UI, the `tuneox` CLI and the MCP server (see "Automation" in the architecture doc). Don't build UI-only features.
- Features that are paid in rekordbox are free in TuneOx. Never add plan gating or license checks.

Test hardware: an XDJ-AZ (reads OneLibrary) is always available; CDJ-3000s (read Device Library) are available through friends. See [research/usb-export.md](research/usb-export.md) for which player reads which format.

## Reverse engineering rekordbox with REA

REA (MCP server `rea`, CLI `npx rea-agents`) is set up with Ghidra as the native provider. Target: `/Applications/rekordbox 7/rekordbox.app` (v7.2.9). It's a JUCE C++ app with RTTI class names intact, so searching symbols by class name (e.g. `DeviceLibraryPlusDlgManager`, `CloudExportDialog`) is the fastest way in.

Workflow:

1. Check prior work first: Deep Symmetry's DJ Link analysis, rekordcrate, pyrekordbox. Only reverse engineer what they don't cover or what changed in rekordbox 7.
2. Raw output (pseudocode, disassembly, Ghidra projects, dumps) goes in `.re/`, which is gitignored.
3. Write what you learned in your own words in `research/<topic>.md`: structures, field meanings, byte layouts, constants, behavior, and the evidence (function name/address, sample file).
4. Implement from the research notes.

Never commit decompiled Pioneer code, Pioneer binaries or libraries, or anything from the app bundle (skins, models, MIDI mapping CSVs, demo tracks, sample packs). The repo is public, and this keeps it safe from takedowns. TuneOx code is always written by us.

## Test data

- The user's real library is at `~/Library/Pioneer/rekordbox/master.db`. Open it read-only, or better, copy it into `.re/fixtures/` first. Never write to it.
- Real exports and user databases stay in `.re/`. Committed test fixtures must be generated by our own code or built from scratch.
- `.re/fixtures/usb-rockittrax6/` holds copies of the databases from one of the user's real gig sticks. Never write to a mounted USB stick except as part of an export the user asked for.

## Commands

Rust comes from Homebrew's keg-only `rustup`, so put it on PATH first:

```bash
export PATH="/opt/homebrew/opt/rustup/bin:$PATH"
```

```bash
cargo build                                   # whole workspace
cargo test --workspace
cargo clippy --workspace --all-targets
cargo fmt --all
cd apps/desktop && bun install && bun run tauri dev   # run the desktop app
```

The rekordbox database keys (`TUNEOX_MASTERDB_KEY`, `TUNEOX_ONELIBRARY_KEY`) are compiled in by `crates/tuneox-pioneer/build.rs`, from the environment or from the gitignored `.keys.env` at the repo root. CI and release builds get them from GitHub Actions secrets. Never write the key values into source, docs or commit messages.

The `tuneox` CLI (`apps/cli`) runs any core command. Use a scratch library under `.re/` when testing against real data, so the user's real TuneOx library isn't touched:

```bash
cargo run -p tuneox-cli -- --library .re/tuneox-test-library.db import-rekordbox --dry-run
cargo run -p tuneox-cli -- --library .re/tuneox-test-library.db search --bpm-min 124 --bpm-max 128 --compatible-with 8A
cargo run -p tuneox-cli -- commands --json        # the command catalog with JSON schemas (= MCP tools)
cargo run -p tuneox-cli -- run get_track '{"id": 1}'
```

MCP server: `tuneox mcp` serves every command over stdio (`crates/tuneox-mcp`, both the 2026-07-28 stateless protocol and the older `initialize` handshake). The user's Claude Code has a user-scope MCP entry `tuneox` pointing at `~/.local/bin/tuneox mcp`, which uses the real library in `~/Library/Application Support/TuneOx/`. After changing commands, reinstall the binary and restart Claude Code:

```bash
cargo install --locked --path apps/cli --root ~/.local
```

Research tools for rekordbox's SQLCipher databases (prints the schema, or runs a query) and analysis files:

```bash
cargo run -p tuneox-pioneer --example rbdb -- masterdb .re/fixtures/master.db
cargo run -p tuneox-pioneer --example rbdb -- onelibrary .re/fixtures/usb-rockittrax6/exportLibrary.db "SELECT ..."
cargo run -p tuneox-pioneer --example anlz_dump -- path/to/ANLZ0000.EXT
```

REA notes:

- REA needs Node 22, 24 or 26+. Node 24 is installed via nvm at `~/.nvm/versions/node/v24.21.0`; put its `bin` first on PATH when running the CLI.
- Ghidra (Homebrew, `GHIDRA_INSTALL_DIR=/opt/homebrew/opt/ghidra/libexec`) can't import universal Mach-O binaries. Thin them into `.re/bin/` first:

```bash
lipo -thin arm64 "/Applications/rekordbox 7/rekordbox.app/Contents/MacOS/rekordbox" -output .re/bin/rekordbox.arm64
```
